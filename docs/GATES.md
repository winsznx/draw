# Gates

This is a hackathon process record of DRAW's gate verdicts, and it only points at the `result.json` files that scripts wrote. The product is in [PRODUCT.md](PRODUCT.md), and how to check each claim is in [PROOF.md](PROOF.md).

A gate is a check the build had to pass before the next step could rely on it. Each verdict below is copied from a result file a script wrote. Older runs are kept and never overwritten, and failed runs stay on record with their cause. Updated 2026-10-06.

## Four locks

The four locks are the project's own maturity checks for the market, the use of Canton (the sponsor technology), what a judge sees, and the mechanism. Each row says what evidence changed it and what would move it to LOCK. LOCK means the evidence is enough for this pass. REVISE means it isn't yet, and the last column says what would move it. "Close" marks a REVISE that's near LOCK.

| Lock | State | Evidence that changed it | What would move it |
|---|---|---|---|
| MARKET_LOCK | REVISE | Public process evidence only. No practitioner conversation or outside usability test is on file | One conversation with someone who has run capital calls, recorded in [PROBLEM_EVIDENCE.md](PROBLEM_EVIDENCE.md) |
| SPONSOR_LOCK | REVISE, close | The removal test on LocalNet: 4 of 5 attacks land on the database, 0 of 5 on DRAW. On DevNet, Canton Coin settles through CIP-0056 allocations in the scripted run and on the live site. On package 0.3.0 each call also reaches the LP as a CIP-0056 AllocationRequest, and LP A paid from it, through the backend client in the scripted run and with the shared login in the run before. A signed-in LP paid from its own Canton wallet, from DRAW or with Accept in the node's Canton Coin wallet, with the team's own login. The scripted run uses the Keycloak clients NODERS issued for DRAW, the backend client for the seats and the verifier client for the read-back | Separate credentials per party on DevNet: a verifier client that only reads, a sign-in run with a second person's login, or LPs that hold their own keys |
| JUDGE_LOCK | REVISE | The live web app on DevNet, with passing browser journeys there and on LocalNet, the proof page, a demo script for the current UI, the brief, the pilot plan, and a rubric map against the six published criteria. The portfolio check ([PORTFOLIO_NOVELTY.md](PORTFOLIO_NOVELTY.md)) came out ADJACENT: the product is distinct from the builder's earlier ones, and its proof-console style is one the builder has used before. A deck draft exists and hasn't been reviewed. No video yet | A recorded demo that opens on the fund, and the reviewed deck |
| MECHANISM_LOCK | REVISE, close | Privacy, settlement, failure, replay, the database comparison and the read-back held on LocalNet plus 100 generated cases. The canonical flow passed on DevNet on packages 0.2.0 and 0.3.0, including transaction streams, and on the NODERS clients with the read-back on a login the ledger refused when it tried to act as the fund. Browser journeys pass on both networks, and on DevNet a signed-in LP reads and pays with its own token | LP-from-LP credential separation on DevNet, for example a sign-in run with a second person's login |

No lock is LOCK. Mechanism and Sponsor are close. Market is the weakest.
