# Judge scorecard

This hackathon process record is the team's own check against the six judging criteria, used to decide what to work on next. Judges score separately. The product is in the [README](../README.md) and [PRODUCT.md](PRODUCT.md), and the proof in [PROOF.md](PROOF.md).

Checked on 2026-10-07 against what exists that day. Plans don't count as done.

| Criterion | What exists today | What's missing and the next action |
|---|---|---|
| Value / Problem Statement | The job and what goes wrong in it, from 12 public sources. 2 argue against, and 3 show fiat tools already handle notices and matching ([PROBLEM_EVIDENCE.md](PROBLEM_EVIDENCE.md)). Why now: CIP-0056 allocations carry the reference inside the payment, and USDCx is a CIP-0056 token whose registry lists the allocation API DRAW settles through. DRAW hasn't run with USDCx | No practitioner has confirmed the problem. Next: 3 to 5 conversations with people who run capital calls or pay into them |
| ICP / Audience | Built for the fund COO or operations lead at an emerging manager, with an outsourced fund administrator as the first channel, an actor map and a named payer. All of it is a hypothesis from public sources ([icp.md](pitch/materials/icp.md)) | No LP-count band or calls per year until the interviews give them. Next: the same conversations |
| Metrics / Validation | Test evidence, each with its network ([metrics.md](pitch/materials/metrics.md)). 83 of 83 checks in the scripted DevNet run on package 0.3.0 where each party signs with its own key, all five keys on one machine, and 82 of 82 in the one where DRAW's backend login signs for every demo seat. The live-site journeys on DevNet, including an LP signed in with HackCanton, with the team's own login. 76 of 76 checks on LocalNet with each party signing with its own key, and 100 seeded calls and the database comparison, also on LocalNet | 0 conversations and 0 usability tests as of 2026-10-07. Next: the conversations, and 2 to 3 fifteen-minute usability tests on the live site |
| GTM Materials | First channel: one outsourced administrator serving several emerging managers. A three-stage pilot that starts with a shadow run of one real call where no money moves, and a pricing hypothesis ([gtm.md](pitch/materials/gtm.md), [PILOT_PLAN.md](PILOT_PLAN.md)) | No outreach results and no pricing conversation. Nobody has agreed to a pilot. Next: outreach, with the pricing question in every interview |
| MVP Materials | A live web app on the HackCanton DevNet node. CIP-0056 settlement executed inside the notice's settle choice, and each LP's call also reaching it as a CIP-0056 AllocationRequest. Per-party reads and transaction streams, browser journeys on both networks, and each party signing with its own key on LocalNet and in a scripted DevNet run. An LP can sign in with its own HackCanton login and pay from its own Canton wallet, including with Accept in the node's Canton Coin wallet | On the live DevNet site one backend client acts for every demo seat, the DevNet run with each party's own key kept all five keys on one machine, and every sign-in run used the team's own login as the LP. Next: a sign-in run with a second person's login, keys held by separate people, and a clean-room run of the current web app |
| Pitch Materials | The README opens with the product, then the live tour. An 11-slide deck v1, re-exported on 2026-10-07 after the fixes listed in [SUBMISSION.md](SUBMISSION.md#links), and drafts of the six platform materials, none reviewed by the owner yet | No video. Next: the video, then the owner's review of the deck and the materials |

The weakest part is validation with real people, which Metrics, ICP and GTM all rest on. The strongest is the working product and its evidence. Five of the six criteria are about the business and the pitch, so conversations, the deck and the video come first in the time left.

The evidence behind each criterion, and where a judge finds it, is in [RUBRIC_ARTIFACT_MAP.md](RUBRIC_ARTIFACT_MAP.md).
