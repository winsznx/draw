# DevNet deployment

This is the record of DRAW on the HackCanton DevNet node: what the organizers and NODERS provided, the clients and parties DRAW runs with and their rights, how to repeat a run, what each run showed, and the limits that apply on DevNet only. The canonical run, on 2026-10-07 with five external parties that each signed their own transactions with their own key, passed 83 of 83 checks on package 0.3.0, plus two credential checks skipped with their reasons recorded ([Record](#record)).

In that run the node prepared each transaction and the acting party's own Ed25519 key signed it. All five keys sat on the machine that ran the script, so the run shows that the ledger needs each party's signature. It doesn't show that separate people held the keys. One login, the team's own, submitted for every party and read each settlement back. Earlier that day, run 20261007T125638Z passed 82 of 82 with the demo seats on the backend client NODERS issued for DRAW and the read-back on the verifier client, which by then could only read as the fund. Before that, run 20261006T131900Z passed 82 of 82 on the same two clients on 2026-10-06, while the verifier client could still act for the team's personal wallet party. The earlier PASSes are 79 of 79 on 0.3.0 with one shared hackathon login for every party and the read-back, and 72 of 72 on package 0.2.0 on 2026-10-04. Two runs before the first PASS aborted on run-script bugs, a dirty-tree PASS earlier on 2026-10-06 was superseded, and the first run with external parties stopped at the read-back. All are kept. The live web app runs on the same node ([DEPLOY.md](DEPLOY.md)). Since about 13:25 UTC on 2026-10-06 its demo seats act through the backend client, since about 13:00 UTC on 2026-10-07 its read-back step reads through the verifier client, and sign-in uses DRAW's own web client. The live site doesn't use the external parties. An LP signed in with a HackCanton login has also joined demo funds as itself and paid from its own Canton wallet, in runs that all used the team's own login as the LP.

## What the organizers provided (2026-10-04)

NODERS hosts one shared DevNet participant for HackCanton (`hackcanton-01`). From their [quickstart](https://hackmd.io/@IzUWaelHTRa_fG1NRW376w/HkBpCR5YGx):

| Item | Value |
|---|---|
| JSON Ledger API | `https://ledger-api-json.participant.hackcanton-01.devnet.naas.noders.services` |
| Login | Keycloak realm `noders-appsfactory`, client `web-app-ui-hackcanton-01-devnet`, password grant then refresh token. Token `sub` is the ledger user |
| Validator and Scan proxy | `https://validator-api-http.validator.hackcanton-01.devnet.naas.noders.services`, Splice 0.8.4 (checked 2026-10-04). Token Standard registry under `/api/validator/v0/scan-proxy/registry` (Splice release notes: token-standard endpoints exposed on the scan proxy) |
| Parties | Created in the web Console, namespaced to the team, up to 20. The account's ledger user gets act-as and read-as on each |
| DAR upload | Web Console, Collections, Upload DAR |
| Canton Coin | Wallet faucet (TAP), or `AmuletRules_DevNet_Tap` through the ledger |
| Errors | The node returns a trace id instead of the cause. Look it up in their Grafana |

Consequence: one hackathon account is one credential for every party it creates. A DevNet run with one account proves party-scoped visibility and on-ledger settlement. It can't show credential separation, so it records `credentialSeparation: NOT_TESTED_SINGLE_CREDENTIAL`. We asked NODERS for machine-to-machine clients on 2026-10-04, and on 2026-10-06 they issued three Keycloak clients for DRAW (next section). On 2026-10-07 they also allocated five external parties for DRAW ([External parties](#external-parties-noders-allocated-for-draw-2026-10-07)).

## External parties NODERS allocated for DRAW (2026-10-07)

A team can't allocate external parties on this node. That takes a participant admin, an identity provider admin, or the self path, whose quota defaults to 0 in Canton 3.5. Our own `/v2/parties/external/allocate` call is refused with HTTP 403. That was first reported on 2026-10-04 without saved output, and the read-only probe [20261006T091205Z](../evidence/devnet/probes/20261006T091205Z/result.json) saved it, along with `generate-topology` and a prepare-only interactive submission working for our login. The later probes got the same 403 with the backend client. So DRAW generated an Ed25519 key and an onboarding transaction per party, signed each with its party's key, and NODERS allocated the five parties on 2026-10-07. Sources and probe details are in [SPONSOR_FINDINGS.md](SPONSOR_FINDINGS.md).

`b94ab230-ext-1` is the fund, `-ext-2` to `-ext-4` are LP A, LP B and LP C, and `-ext-5` is the unrelated party. Each party id ends in its own key's fingerprint. The keys sit in the gitignored `.keys/` folder on the machine that ran the script. The team's own login submits and reads for these parties, but the ledger accepts a transaction for one only with that party's signature. The backend client has no rights on them, the verifier client can't read them, and the live site doesn't use them.

## Runbook with the NODERS clients

This is how runs [20261006T131900Z](../evidence/devnet/runs/20261006T131900Z/) and [20261007T125638Z](../evidence/devnet/runs/20261007T125638Z/) ran.

1. Onboard once in the Wallet ("Onboard yourself") with the team's HackCanton login. In the Console, create parties `draw-admin`, `draw-lpa`, `draw-lpb`, `draw-lpc`, `draw-outsider`, and upload the committed [contracts/dist/draw-0.3.0.dar](../contracts/dist/draw-0.3.0.dar) under Collections (or `contracts/daml/.daml/dist/draw-0.3.0.dar` after a local build, which has the same package id). 0.3.0 is a Smart Contract Upgrade of 0.2.0, which the node already had from 2026-10-04. The backend client needs act rights on those five parties, which NODERS set up for DRAW's.
2. In `.env`, uncomment the HackCanton DevNet block from [.env.example](../.env.example) with `LEDGER_AUTH_MODE=oauth`, the five party ids copied from the Console, `DRAW_BACKEND_CLIENT_ID` and `DRAW_BACKEND_CLIENT_SECRET`, and for the read-back `DRAW_VERIFIER_CLIENT_ID` and `DRAW_VERIFIER_CLIENT_SECRET`. Leave `DRAW_BACKEND_USER` and `DRAW_VERIFIER_USER` unset. Each is read from its token's subject, and one that is set and disagrees with its token stops the run.
3. `node scripts/demo/probe.mjs` records what each client may do, without changing the ledger. Evidence goes to `evidence/devnet/probes/<runId>/`.
4. `node scripts/demo/run.mjs`. Evidence goes to `evidence/devnet/runs/<runId>/`. With both clients the run records `seatCredential: backend-client` and `credentialSeparation: VERIFIER_ONLY`.
5. For the app, see [DEPLOY.md](DEPLOY.md). The live API has the backend client and, since about 13:00 UTC on 2026-10-07, the verifier client, and no person's login.

## Runbook with one hackathon account

This is how the runs before 13:19 UTC on 2026-10-06 ran, with the team's personal login acting for every party and the read-back.

1. Onboard and create the parties as in step 1 above.
2. In `.env`, uncomment the HackCanton DevNet block from [.env.example](../.env.example) with `LEDGER_AUTH_MODE=password`, and set `HACKCANTON_USERNAME`, `HACKCANTON_PASSWORD` and the five party ids.
3. `node scripts/demo/run.mjs`. Evidence goes to `evidence/devnet/runs/<runId>/`. The run records `credentialSeparation: NOT_TESTED_SINGLE_CREDENTIAL` and skips both credential checks.

## Runbook with external parties

This is how run [20261007T130259Z](../evidence/devnet/runs/20261007T130259Z/) ran, with the team's personal login submitting what each party's key signed.

1. NODERS allocates the five parties from onboarding transactions signed with their keys, as in [External parties](#external-parties-noders-allocated-for-draw-2026-10-07). Each key is in `.keys/`, named `DRAW_EXTERNAL_KEY_PREFIX` plus the role, `devnet-ext-` by default.
2. In `.env`, uncomment the HackCanton DevNet block from [.env.example](../.env.example) with `LEDGER_AUTH_MODE=password` and the team's `HACKCANTON_USERNAME` and `HACKCANTON_PASSWORD`, set `DRAW_PARTY_MODE=external-provisioned`, and point `DRAW_EXTERNAL_PARTIES_FILE` at NODERS' list of the allocated parties. Leave `DRAW_VERIFIER_*` unset. The verifier client can't read the external fund party, so the read-back runs on the team's login.
3. `node scripts/demo/run.mjs`. Evidence goes to `evidence/devnet/runs/<runId>/`. The run records `custody: EACH_PARTY_SIGNS_WITH_ITS_OWN_KEY`, `seatCredential: shared-login` and `credentialSeparation: NOT_TESTED_SINGLE_CREDENTIAL`, adds the `CUSTODY` gate, and skips both credential checks.

## Runbook with one client per role

1. Copy [.env.example](../.env.example) to `.env`. Set `DRAW_NETWORK=devnet`, `DRAW_JSON_API`, `OAUTH_TOKEN_URL`, `OAUTH_AUDIENCE`, `OAUTH_SCOPE`, `REGISTRY_URL`, `SCAN_URL`, and `SCAN_AUTH_USER` if Scan sits behind the validator's proxy.
2. Parties:
   - If the organizers provide parties: fill `DRAW_<ROLE>_PARTY` and the OAuth client id and secret for admin, lpA, lpB, lpC, outsider, and the verifier user (readAs admin only). The user ids are optional, read from each client's token.
   - If they provide a participant-admin user: set `DRAW_OPERATOR_*`, run `node scripts/demo/provision.mjs devnet-draw`, paste the output into `.env`, then create one OAuth client per printed user.
3. Package: with `DRAW_OPERATOR_*` set, the run uploads `contracts/daml/.daml/dist/draw-0.3.0.dar` if it was built locally, and the committed [contracts/dist/draw-0.3.0.dar](../contracts/dist/draw-0.3.0.dar) otherwise. Without it, upload the DAR through whatever path the organizers give, and the run checks the package id is present.
4. Faucet: the run taps 100 Amulet per LP with `AmuletRules_DevNet_Tap`. If DevNet disallows that, fund the LPs from the wallet faucet and set `DRAW_TAP_AMOUNT=0`.
5. Run `node scripts/demo/run.mjs`. Evidence goes to `evidence/devnet/runs/<runId>/`. The gate is `DEVNET_E2E` in `result.json`. With a separate user per seat and for the verifier, it records `credentialSeparation: TESTED`.
6. Restart check: stop and start the app server, then confirm the fund, obligations and receipts render again from the ledger (`node app/server.mjs` with `DRAW_NETWORK=devnet`).
7. Run the campaign and the browser journey against DevNet if traffic allows. Keep DevNet and LocalNet evidence separate.
8. Fill in the Record below from the run's own files, then update [claims.yaml](../claims.yaml), [GATES.md](GATES.md) and [SPONSOR_FINDINGS.md](SPONSOR_FINDINGS.md), marking DEVNET_VERIFIED only what ran.

## Sign in with HackCanton on this node

DRAW's own public client `xidoncapitals-web-app-hackcanton-01-devnet` runs the authorization code flow with PKCE for the live site, back to https://drawcalls.xyz/auth/callback. The first four sign-in runs used NODERS' public client `web-app-ui-hackcanton-01-devnet`, the same one the password grant above uses. The browser then reads the login's wallet party from `GET /v2/authenticated-user` (`primaryParty`), reads and accepts on the JSON Ledger API, and pays through the validator's wallet API, all with the LP's own token. A login whose party isn't onboarded yet has to open the node's Canton Coin wallet once. Variables and CORS are in [DEPLOY.md](DEPLOY.md#sign-in-with-hackcanton), and the endpoints are in [SPONSOR_FINDINGS.md](SPONSOR_FINDINGS.md).

## Limitations specific to DevNet

- In each run one credential acts for every party, the backend client for the demo seats and the team's own login in the run with external parties, so LP-from-LP credential separation is shown on LocalNet only.
- The verifier client reads only as the regular fund party, so in the run with external parties the team's own login, which submitted for every party, also read each settlement back.
